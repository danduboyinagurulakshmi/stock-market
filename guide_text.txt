Stacking results with UNION ALL
UNION ALL  puts the rows of one SELECT underneath another. Both SELECTs must return the same number
of columns in the same order. A text literal like 'tcs' AS stock  adds a column that says which table each

Moving averages
Goal. Create a table bajaj1  with date, close_price, ma20, ma50 . ma20  is the average close of the
current day and the previous 19 trading days; ma50  the same over 50 days. Round both to 2 decimals.
Leave them NULL until a full window of days exists.
You'll use: window functions: AVG() OVER , ROWS BETWEEN , ROW_NUMBER() , CASE , CREATE TABLE … AS
How a window function works
A normal aggregate like AVG(close_price)  squashes many rows into one. A window function computes
the aggregate for every row, looking at a 'window' of neighbouring rows, and keeps all rows.
Here is a toy table with a 3-day moving average. The window for each row is 'this row and the 2 before it':
day price rows in the window 3-day avg
1 10 10 should be NULL
2 12 10, 12 should be NULL
3 11 10, 12, 11 11
4 13 12, 11, 13 12
5 15 11, 13, 15 13
In SQL, that window is written AVG(price) OVER (ORDER BY day ROWS BETWEEN 2 PRECEDING AND
CURRENT ROW) . On days 1 and 2 SQL still returns a number — it just averages whatever rows exist. A '3-
day' average of one day is not a 3-day average, so you have to blank those rows out yourself.
ROW_NUMBER() OVER (ORDER BY day)  tells you which row you're on.
Your job is to adapt this from 3 days to 20 and 50.
Start small: SELECT date, close_price FROM bajaj_auto ORDER BY date;1
Add a raw 20-day average using the pattern above. How many PRECEDING  rows make a 20-row window?
(Not 20.)

CREATE TABLE bajaj1 AS
SELECT
  date,
  close_price,
  CASE WHEN ROW_NUMBER() OVER (ORDER BY date) >= ___
       THEN ROUND(AVG(close_price) OVER ( ___ ), 2)
  END AS ma20,
  -- ma50: same idea, you write it
FROM bajaj_auto;

889 rows, 4 columns, in the order date, close_price, ma20, ma50 .
The first non-NULL ma20  is on 2015-01-29 and equals 2415.53.
The first non-NULL ma50  is on 2015-03-13 and equals 2283.80.
On 2018-07-31, ma20  is 2918.51.
If your first ma20  lands on 2015-01-30 instead, you've built a 21-day window.
Common mistakes
Off by one. ROWS BETWEEN 20 PRECEDING AND CURRENT ROW  is 21 rows.
Missing ORDER BY inside OVER. Without it the 'previous rows' are in no defined order.
Partial windows. Skipping the CASE means the first 19 and 49 rows carry fake averages, and those
fake values can trigger fake signals in task 7.
Putting a comma after the last column before FROM .
Still stuck? Read one nudge at a time
1. The frame is ROWS BETWEEN n PRECEDING AND CURRENT ROW . For a 20-row window, n + 1 = 20.
2. The CASE condition compares the row number with the window size: row 20 is the first row that has 20
rows behind it (including itself).
3. Build and run the ma20 column on its own first. Only then copy it for ma50.

Golden cross signals
Goal. Using bajaj1 , create bajaj2  with date, close_price, signal . Buy on the day ma20  crosses
above ma50 , Sell on the day it crosses below, Hold on every other day — including days where today's or
yesterday's averages are NULL.
You'll use: LAG() , a CTE ( WITH ), CASE  with several conditions
A cross is about two days, not one
' ma20  is above ma50 ' is true on hundreds of days in a row. A crossover happens on the single day that
changes: yesterday it wasn't above, today it is.
date ma20 ma50 yesterday ma20 yesterday ma50 signal
Mon 98 100 — — Hold
Tue 99 100 98 100 Hold
Wed 101 100 99 100 Buy
Thu 103 101 101 100 Hold
Fri 100 101 103 101 Sell
Wednesday is a Buy because yesterday ma20 ≤  ma50  and today ma20 > ma50 . Thursday is still above,
but nothing changed, so it's Hold.
LAG(ma20) OVER (ORDER BY date)  gives you the previous row's ma20  — the 'yesterday' columns above.
You can't use a window function inside a WHERE  or refer to its alias in the same SELECT, so compute the
lags in a CTE first, then write the CASE in the query that reads from it.
Write a CTE t  that selects everything from bajaj1  plus prev_ma20  and prev_ma50  using LAG .1
Below it, SELECT * FROM t LIMIT 60;  and eyeball rows 49–52. You should see prev_ma50  become

  CASE
    WHEN ___  IS NULL OR ___  IS NULL           THEN 'Hold'

Adjusting a price series
In a 1:1 bonus issue, every shareholder gets one extra share for each share they own. The number of
shares doubles, so the price halves overnight — but nobody gained or lost anything. To compare prices
across that date, divide every price before the event by the adjustment factor (here, 2). Prices on and after
the event date stay as they are.
The event date is the first day the price trades at the new level — the date you found in task 12.
WITH adjusted AS (
  SELECT 'TCS' AS stock, date,
         CASE WHEN date < ' ___ ' THEN close_price / 2 ELSE close_price END AS adj_close
  FROM tcs
  UNION ALL
  ___
)
SELECT stock,
       ROUND(100.0 * ( ___  / ___  - 1), 1) AS adjusted_pct_change
FROM adjusted
GROUP BY stock
ORDER BY stock;
